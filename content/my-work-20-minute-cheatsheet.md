## 4 — Project 1: Retail credit risk system (the flagship)

**One public loan book taken through the whole credit risk chain a bank runs: who will default, what a default costs, what to provide for, and what capital to hold.**

| | |
|---|---|
| Data | 466,285 public LendingClub personal loans, 36 or 60 months, issued 2007–2014; 2014 held back as the out-of-time (OOT) test |
| Default | Charged off, or more than 30 days late and heading there; 3.44% of loans |
| Status | Live, public repository |

**The flow:** raw loans → define default → WoE binning → PD models A and B → scorecard → validation → LGD and EAD → lifetime PD → IFRS 9 staging and ECL, with a CECL comparison → macro scenarios → Basel IRB capital → vintage curves, monitoring dashboard.

| Result | Value | Read it as |
|---|---|---|
| Model B AUC, test / OOT | 0.6817 / 0.6923 | Ranks defaulters above good borrowers about 69% of the time, and holds up on unseen years |
| Gini, KS | 0.36–0.38; 0.27–0.28 | Modest, because LendingClub had already screened every borrower |
| The bar to beat | LendingClub's own sub-grade scores 0.6886 OOT | The platform's pricing already carried most of the signal |
| LGD | About 93% | Unsecured loans recover little |
| Expected loss | USD 58.67 million, 3.21% of exposure | PD × LGD × EAD across the full book |
| Hosmer–Lemeshow, OOT | p = 0.001 | On hundreds of thousands of loans, tiny calibration gaps become "significant"; read with the per-grade view |

| Decision | Why |
|---|---|
| Logistic regression on weight-of-evidence bins, not a black box | Explainable to credit and regulators, and it converts into a points scorecard. Checked later: boosting on the same variables did not beat it |
| AUC, Gini, KS instead of accuracy | Predicting "nobody defaults" is 96.57% accurate and useless |
| Out-of-time test | A model must survive years it never saw |
| State the edges plainly | The CCF model is a demonstration on 5,000 simulated revolving accounts (term loans have no undrawn limit); roll rates and the transition matrix are proxies built from one snapshot |

**What it proves:** I know the whole credit risk chain from the inside, and I report a model's limits along with its strengths.

## 5 — Project 2: Parents Health OS

**A family care console I am building for my own parents: check-ins, documents and schedules in one place, with every sensitive step behind a person's review. My most complete live app.**

**The flow:** a parent taps a WhatsApp button → a signed webhook reaches the app → the check-in is stored under that family's access rules → the scheduler plans the next reminder → documents are read by AI, and nothing is saved until a person approves it.

| Building block | Plain meaning |
|---|---|
| Next.js and Supabase | The web app, and the hosted Postgres database with sign-in (Supabase Auth) |
| 15 PostgreSQL tables under row-level security (RLS) | The database itself checks, row by row, who may see what |
| WhatsApp Cloud API button check-ins | Parents reply with one tap on the app they already use |
| HMAC SHA-256 webhooks | Every incoming message carries a signature, so fakes are rejected |
| Compare-and-swap (CAS) scheduler | A job runs only if nothing changed it in between, so duplicate or out-of-order deliveries can't double-send |
| AI document extraction behind human review | AI reads the report; a person approves before it counts |

| Decision | Why |
|---|---|
| Security in the database, not only the app | A bug in the app can't leak another family's data |
| A human gate on AI | Health data is too important to trust unreviewed |
| Claims kept strict | No offline-first, autonomous-operation or diagnosis claims |

**What it proves:** I can ship a real, secure, AI-assisted product end to end.

## 6 — Project 3: The evidence-grounded agent

**A chat agent on my portfolio site that answers questions about my work only from verified evidence, cites it, and refuses anything it can't back.**

**The flow:** question → rate limit → **route** (intent: profile, role fit, project, experience, education, skills, limitations or unknown) → **retrieve** from a 15-record evidence corpus → **generate** with Gemini 2.5 Flash (or a deterministic local answer when no key is set) → **verify**: strip any unsupported claim, or refuse → stream the answer.

| Guardrail | How |
|---|---|
| Refusal | "I don't have verified public evidence for that." when nothing matches |
| Claim-safety rules | Exact wording for sensitive facts: "Independent Practice", never "freelance"; no production multi-agent claims |
| Retired projects | No evidence records remain, and tests check they are rejected |
| Rate limit | 10 requests a minute per session cookie |

| Evaluation, 22 cases | Result |
|---|---|
| Retrieval hit | 17/17 |
| Refusal correctness | 10/10 |
| Retired-claim rejection | 3/3 |
| Citation validity | 17/17 |
| Source precision | 17/17 |

**Stack:** Next.js 16, React 19, Tailwind 4, an Edge API route; lint, type-check, evals and build all clean.

**What it proves:** I build AI the way a bank would want it: grounded, cited, tested, with refusal as a feature.

## 10 — Quant work

**Client equity strategies.** The strategies were the client's; I engineered the Python backtest suite that tests them, on a 500-stock US universe over 10 years.

| Script | What it does |
|---|---|
| Strategy engine | Filters stocks (debt, earnings quality, multi-factor, AI predictions), ranks them by factors within each sector, picks and weights them, rebalances; handles survivorship bias and implementation lag |
| Performance and robustness | Annual return, volatility, Sharpe and Sortino, maximum drawdown, tracking error, information ratio, rolling 1- and 3-year views, factor regressions, CAPM |
| Diversification, turnover, liquidity | Turnover by strategy, sector attribution, effective number of stocks |
| Turnover optimiser | Moves weights as little as possible towards target (L1 against L2 norms), under a hard turnover limit, to cut trading costs |

**SARIMA forecasting.** Monthly antidiabetic drug prescriptions in Australia, July 1991 to June 2008 (204 months).

**The flow:** plot → STL decomposition (trend plus yearly season) → ADF stationarity tests (p = 1.0 raw; 0.12 after one difference; 0.00 after a seasonal difference too) → train on 168 months, test on the last 36 → 625 candidate orders ranked by AIC → SARIMA(2,1,3)(1,1,3)<sub>12</sub> → residuals pass Ljung–Box (white noise) → rolling 12-month forecasts.

| Model | MAPE on the 36 test months |
|---|---|
| Seasonal naive (repeat last year) | 12.69% |
| **SARIMA** | **7.90%** |

**Churn network.** 10,000 bank customers, about one in five leaving; a Keras neural network judged on **recall**, because a missed churner costs more than a false alarm.

| Model | Recall | Precision | AUC |
|---|---|---|---|
| First network | 0.48 | 0.79 | 0.85 |
| Trained on SMOTE-balanced data | **0.75** | 0.51 | 0.85 |

**Read it as:** SMOTE moved where the model draws its line, not how well it ranks (AUC unchanged), so recall rose while precision fell.

**What it proves:** I pick the metric for the business cost, and I always beat a baseline before trusting a model.
