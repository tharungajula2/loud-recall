Everything below is one system seen from six heights. The lens is production: what is actually built, what it costs, and what breaks. Model names, prices and hardware are stated as at September 2026 and will age; the layer structure will not.

Permanent rule

The model is one layer of six. Almost every production failure happens in the other five.

1. A model is a file of numbers

A trained model is a file. Inside it are weights — floating-point numbers, arranged in matrices, produced by training and then frozen. Nothing else. There is no database inside it, no index of facts, no code that runs logic. Running a model means multiplying an input through those matrices and reading what comes out.

Two numbers describe any model file, and between them they determine almost everything downstream.

PropertyWhat it isWhat it decides
Parameter countHow many weights, in billionsCapability ceiling, and file size
PrecisionBytes used to store each weightFile size, memory needed, accuracy loss
Formula & worked sizing
File size = parameters × bytes per parameter
PrecisionBytes / Param70B Model File Size

FP81 byte70 GB
INT40.5 bytes35 GB

That arithmetic is the hinge of the entire hardware layer. A 70-billion-parameter model at full precision does not fit on any single GPU shipping today. At four-bit precision it fits on one. The model has not changed. The economics have changed by an order of magnitude.

Mental model

A model is a compressed, lossy, statistically-derived representation of its training data, stored as numbers. It knows nothing after its training cut-off, holds no memory between calls, and cannot look anything up unless a layer above it does the looking.

2. The token is the unit everything is counted in

Models do not read characters or words. Text is broken into tokens — sub-word fragments produced by a tokeniser trained alongside the model. Common words are one token; rare words split into several; whitespace and punctuation are tokens too.

Rule of thumbEnglishCode
Tokens per word~1.3~2.0
Characters per token~4~3
Tokens per A4 page~600~900

Tokens are the unit of pricing, the unit of the context window, the unit of throughput, and the unit of the rate limit. Every cost question in this document eventually reduces to how many tokens moved.

The context window is the number of tokens the model can attend to in one call — prompt, retrieved documents, conversation history and the response, all counted together. Frontier windows now run to one million tokens on several models. A large window is not free: attention cost grows steeply with sequence length, and the KV cache that holds it consumes GPU memory linearly.

Permanent trap

Treating the context window as storage. Filling a one-million-token window on every call multiplies cost and latency while usually degrading answer quality, because the relevant fact is now buried in noise. Retrieval exists to put less in the window, not more.

3. Training and inference are different businesses

The same word — running a model — describes two activities with opposite economics.

FrequencyOnce, then occasionallyEvery request, forever

ParallelismAcross thousands of GPUsAcross concurrent requests

Key insight

Training is bound by how fast a chip can multiply. Inference is bound by how fast weights can be moved from memory into the multiplier. This is why an accelerator's memory bandwidth, not its peak FLOPS, is the number that predicts serving cost — and why memory capacity has become the axis on which hardware vendors now compete.

A production AI system is six layers deep. Read bottom to top, each layer consumes the one beneath it and is invisible to the one above.

The two cross-cutting concerns are not a seventh and eighth layer. They apply at every height, and they are the two that get deferred, because neither produces a demo.

5. What choosing a model does not settle

Model selection consumes most of the public conversation and settles the smallest part of the problem. A team that has chosen a frontier model has decided nothing about retrieval quality, tool reliability, latency budget, failure handling, evaluation, cost ceiling or audit trail — and those are what determine whether the system works.

What the model determines

Reasoning ceiling, instruction following, language and code quality, context length, native modalities.

What the surrounding stack determines

Whether the right information reaches the model, whether actions actually execute, what a failure costs, what the monthly bill is, and whether anyone can explain what happened.

A weaker model with excellent retrieval and tight tool definitions outperforms a frontier model wired to a poor context pipeline, at a fraction of the cost. This is the most reliably observed result in applied work and the most reliably ignored.

6. Why file size decides the machine

Layer 1 · Compute

An accelerator can only run what fits in its memory. Weights must be resident; so must the KV cache holding the conversation so far; so must activations during the forward pass. Exceed the memory and the model must be split across several chips, which introduces interconnect traffic and changes the cost structure entirely.

KV Cache per request (approximate)
2 × layers × kv_heads × head_dim × bytes × sequence_length
Worked example: 70B-class model at FP8, 32k context
Formula expansion 2 × 80 layers × 8 kv_heads × 128 dim × 1 byte × 32,000
Per concurrent request = 5.2 GB
At 40 concurrent requests: 208 GB of cache, against 70 GB of weights
Key insight

At production concurrency the KV cache is usually larger than the model. This is why serving frameworks spend most of their engineering on cache management rather than on matrix multiplication, and why long-context features are expensive in a way the price page does not make obvious.

NVIDIA holds roughly 80% of the AI accelerator market against AMD's 5 to 7%, and its advantage is now more software than silicon: CUDA has a decade of library and tooling depth that ROCm is still closing. Every hyperscaler now designs its own inference chip, for the same reason every airline once bought its own aircraft rather than chartering.

Permanent trap

Buying on peak FLOPS. Inference is bound by memory bandwidth and capacity, not arithmetic throughput. A chip with higher paper FLOPS and lower bandwidth will serve fewer tokens per second per rupee on any large model. Compare bandwidth and memory first, FLOPS last.

8. The interconnect is part of the computer

Layer 1 · Compute

Once a model exceeds one accelerator, the links between accelerators become part of the critical path. A rack-scale system is sold as a single unit for this reason: NVIDIA's NVL72 configuration and AMD's Helios rack both present 72 accelerators as one coherent pool, with the interconnect fabric rather than the individual chip as the product.

TierLinkRough bandwidthLatency character

Each step down is roughly an order of magnitude slower. Parallelism strategy is chosen to keep the most frequent communication at the fastest tier: tensor parallelism inside a node where links are fast, pipeline parallelism across nodes where they are not.

10. How a model is actually made

Layer 2 · Training

Training happens in stages, and the stages do different jobs. A model that has only completed the first stage is not usable as an assistant, whatever its size.

StageWhat happensDataProduces
PretrainingPredict the next token across a vast corpusTrillions of tokens, scraped and licensedA base model — knowledgeable, not helpful
Supervised fine-tuningImitate curated examples of good responsesThousands to millions of demonstrationsA model that follows instructions
Preference optimisationLearn from ranked comparisons of outputsHuman or model preference judgementsTone, refusal behaviour, helpfulness
Reasoning post-trainingReward correct multi-step derivationsVerifiable problems with checkable answersExtended reasoning before answering

The last stage is the substantive change of the past two years. Reasoning-trained models spend additional tokens working before responding, trading latency and cost for accuracy on problems with a verifiable answer. The trade is favourable on mathematics, code and analysis, and roughly neutral on summarisation or drafting, where there is no chain to reason along.

Mental model

Pretraining installs knowledge. Post-training installs behaviour. When a model knows a fact but will not use it correctly, the problem is behavioural and lives in post-training or in the prompt. When it does not know the fact at all, no amount of prompting will conjure it and the answer is retrieval.

11. Four ways to change what a model does

Layer 2 · Training

These are ordered by cost and by how often they are the right answer. The ordering is almost exactly inverse to how often each is reached for.

MethodChangesCostUse whenDoes not fix
PromptingThe instructionFreeAlways, firstMissing knowledge
RetrievalWhat is in contextLow, ongoingThe model lacks the factsWrong output format or style
Fine-tuningThe weights, slightlyModerate, one-off plus servingConsistent format, tone or domain idiomKnowledge gaps, factuality
PretrainingThe weights, entirelyEnormousBuilding a frontier labNothing you have

Fine-tuning is where teams most often spend money on the wrong problem. It teaches a model how to say things, not what is true. A model fine-tuned on a company's documents will adopt the house style and will still invent facts, because fine-tuning does not create a lookup, it adjusts a distribution.

Parameter-efficient adaptation

Full fine-tuning updates every weight and requires memory for the model, its gradients and its optimiser state — several times the inference footprint. LoRA sidesteps this by freezing the base model and training small low-rank matrices alongside it. QLoRA goes further, quantising the frozen base to four bits while training the adapters at higher precision.

Adapter footprint
ApproachFootprint / Memory
Full fine-tune, 70B~1,000 GB training memory
LoRA, rank 16, 70B~200 MB trained adapter
Adapters servable per GPUdozens, hot-swapped
Key insight

Because adapters are small and swappable, one base model on one GPU can serve many tuned variants. This is what makes per-customer or per-domain tuning economically possible, and it is why serving frameworks treat adapter management as a first-class feature rather than an afterthought.

12. Open weights, and what the licence actually permits

Layer 2 · Trainingas at September 2026
Open source

Weights, training code, and data recipe published under a standard licence. Rare at frontier scale.

Open weights

Weights downloadable; training data and full recipe not disclosed. This is what nearly every "open" frontier model means.

The distinction matters because reproducibility differs. Open weights let you run, quantise, fine-tune and audit behaviour. They do not let you verify what the model was trained on, which is the question a regulator or a rights-holder will ask.

Licence shapePermitsWatch for
MIT, Apache 2.0Commercial use, modification, redistributionNothing substantial
Community or customCommercial use, usuallyUser thresholds, naming duties, use restrictions
Research-onlyEvaluationNo production deployment

The open-weight field is no longer a tier below the frontier. DeepSeek-V4-Pro, generally available from August 2026, is a 1.6-trillion-parameter mixture-of-experts model with 49 billion active parameters per token and a one-million-token context window, published under MIT licence with weights released on the same day. Qwen, Mistral and Meta's Muse Spark line ship comparable open releases.

Key insight

A mixture-of-experts model routes each token to a small subset of its parameters. DeepSeek-V4-Pro holds 1.6 trillion weights but activates 49 billion per token — so it must be stored like a 1.6T model and computed like a 49B one. Memory capacity, not compute, is what makes such models hard to self-host.

The strategic picture as at September 2026 is a field splitting in two. Absolute frontier capability is contested by a small group pulling away, while a separate and faster-growing competition runs on cost-effective intelligence at scale, where open-weight models — several of them Chinese — are gaining ground. For batch processing, classification and document work the economics of the second group are difficult to argue against; for long-context agentic tasks their performance remains uneven.

13. One token at a time

Layer 3 · Inference

Generation has two phases with completely different hardware behaviour, and every serving optimisation exists because of the difference.

Every generated token requires reading the entire set of active weights from memory. A 70 GB model producing 50 tokens per second is moving 3.5 TB per second across the memory bus. That is the ceiling, and it is a bandwidth ceiling, not an arithmetic one.

Permanent trap

Optimising the wrong phase. A team complaining about slow responses usually measures total latency, which conflates prefill and decode. Long prompts and long answers have different fixes — caching and prompt reduction for the first, quantisation and speculative decoding for the second. Measure them separately or the optimisation is guesswork.

14. Quantisation

Layer 3 · Inference

Quantisation stores weights at lower numerical precision. Memory falls, bandwidth pressure falls, throughput rises, and accuracy degrades — usually far less than intuition suggests.

FormatBytes/paramTypical useQuality cost
FP16, BF162Training, reference accuracyNone, the baseline
FP81Default on H100 and B200 classNegligible on most models
INT81Older hardwareSmall, task dependent
INT4 AWQ, GPTQ0.5Where VRAM is the binding constraintNoticeable on reasoning tasks
MXFP4, NVFP40.5Newer hardware-native four-bitBetter than legacy INT4

FP8 is the practical default on current datacentre hardware: it halves memory bandwidth requirements with negligible accuracy loss on most model families. Four-bit formats are reached for when memory capacity, not bandwidth, is what binds — fitting a large model onto fewer cards.

Permanent rule

Quantisation is not free and is not uniform. Degradation concentrates on multi-step reasoning and long-context recall, precisely the tasks that are hardest to evaluate casually. Any quantisation change is a change to model behaviour and must be re-evaluated, not assumed.

16. How to read a price page

Layer 3 · Inferenceas at September 2026

Model APIs price input and output tokens separately, and the difference is not cosmetic. Output runs approximately five times input at Anthropic and six times at OpenAI. A verbose model is therefore more expensive than its headline input price suggests, and the gap widens with every reasoning token it emits before answering.

Blended cost of one request
cost = (input_tokens × input_price + output_tokens × output_price) / 1,000,000
Worked example: Document-summary call
Input traffic18,000 tokens @ $3.00 / M
Output generation900 tokens @ $15.00 / M
Single call cost(18,000 × 3 + 900 × 15) / 1,000,000 = $0.0675
At 40,000 calls / month: $2,700

Three structural facts about pricing as at September 2026, each of which changes an architecture decision:

FactConsequence
Output costs 5 to 6 times inputConstrain response length before optimising prompts
Roughly 119-fold spread from cheapest to dearest across the tracked field, on a blended 8:1 basisModel choice is the largest single line item in an AI budget
Reasoning tokens are billed as outputA reasoning model can cost several times a standard one for the same visible answer

The direction of travel has also changed. DeepSeek raised prices in August 2026, its V4-Pro build listing at approximately USD 1.32 input and USD 3.96 output per million tokens — still around seven times cheaper than comparable Western models, but the first deliberate break from the race to zero. Treat further declines as a hope rather than a plan.

Permanent rule

Route by task, not by preference. Cheap, fast models for classification, extraction, routing and drafting; premium models only where the output is final or the reasoning is hard. Tiered routing is the single largest cost lever available at the inference layer, and it requires no model change at all.

17. Embeddings and vector stores

Layer 4 · Data

An embedding is a fixed-length vector of numbers produced by a small model, positioned so that texts with similar meaning sit close together. This makes meaning searchable by distance rather than by keyword.

MeasureComputesUse when
Cosine similarityAngle between vectorsThe default; magnitude is irrelevant
Dot productAngle and magnitude togetherVectors are already normalised
Euclidean distanceStraight-line distanceRarely, for clustering

A vector database stores these vectors with an approximate nearest-neighbour index, trading exactness for speed. The index type is the main decision: graph-based indexes are fast and memory-hungry; quantised indexes are compact and slightly less accurate.

OptionShapeSuits
pgvectorExtension to an existing PostgresMost teams; no new system to operate

Permanent trap

Adopting a dedicated vector database on day one. Below roughly a million vectors, pgvector inside an existing database outperforms a separate service on every axis that matters — latency is adequate, operations are free, and transactional consistency with the source data comes at no cost. The new system is added when a measured limit is hit, not in anticipation.

18. Retrieval that works against retrieval that demos

Layer 4 · Data

Retrieval-augmented generation fetches relevant text and places it in the prompt. The demo version — embed some documents, take the top five matches, paste them in — works on a curated corpus and fails on a real one. The failures are specific and each has a known remedy.

FailureSymptomRemedy
Bad chunkingAnswers cut off mid-thought; tables destroyedChunk on document structure, not character count; keep tables whole
Vector-only searchExact identifiers, codes and names not foundHybrid: lexical and vector, results merged
No rerankingTop matches are similar but not answeringRetrieve widely, then rerank with a cross-encoder
Lost contextChunk is meaningless without its sectionPrepend document and section headings to each chunk
Stale indexConfidently outdated answersRe-embed on source change; carry a timestamp per chunk
No grounding checkFluent claims absent from the sourcesRequire citation spans; verify the answer against them
The retrieval pipeline that survives production
  • query user input
  • → query rewrite resolve pronouns, expand acronyms
  • → hybrid search lexical + vector, retrieve ~50
  • → rerank cross-encoder, keep top ~5
  • → assemble headings, dates, source labels
  • → generate with citation requirement
  • → verify claims traceable to retrieved spans
Key insight

Reranking is the highest-return single addition to a retrieval system. Embedding search optimises for similarity; a reranker optimises for whether the passage answers the question. They are different objectives, and the second is the one that was actually wanted.

19. MCP and the tool interface

Layer 4 · Dataas at September 2026

A model can only affect the world through tools. A tool is a function description the model can call — a name, a purpose, typed parameters — and a runtime that executes the call and returns the result. Before any standard existed, every application wrote its own integration against every system it touched.

The Model Context Protocol standardises that surface. Introduced by Anthropic in November 2024 and donated to the Agentic AI Foundation, a directed fund under the Linux Foundation, in December 2025, it is now governed as a vendor-neutral standard with native support across the major providers. Across the Tier 1 SDKs it sees close to half a billion downloads a month.

ConceptWhat it is
HostThe application the person interacts with
ClientThe connector inside the host, one per server
ServerThe process exposing capabilities over the protocol
ToolsFunctions the model may call, with typed arguments
ResourcesData the host may read into context
PromptsReusable templates the server offers
ElicitationA server requesting input or approval from the person mid-flow

The July 2026 specification moved the protocol core to a stateless design with header-based routing and cacheable list results, resolving the earlier conflict between in-memory sessions and horizontally scaled cloud deployment. The practical effect is that MCP servers can now run behind ordinary load balancers and at edge-worker scale.

MCP

Connects a model to tools and data. Vertical: the agent reaches downward to systems.

A2A

Connects agents to each other. Horizontal: coordination between independent agents.

They are complementary rather than competing, and forcing inter-agent messaging through MCP alone produces unnecessary complexity.

Permanent trap

Connecting write-capable tools before read-only ones have proved reliable. A tool that can send, post, transfer or delete converts a model error into a real-world consequence with no undo. Production sequence: read-only first, then writes behind explicit human approval, then unattended writes only where the blast radius is bounded and the action is reversible.

20. A workflow is not an agent

Layer 5 · Agents

The word agent covers two things that behave nothing alike, and conflating them is the most expensive mistake at this layer.

Workflow

The developer fixes the sequence. The model fills defined slots — classify, extract, draft. Control flow is code. Behaviour is predictable and testable.

Agent

The model chooses the sequence. It decides which tool to call, in what order, and when the task is complete. Control flow is a model output. Behaviour is emergent.

WorkflowAgent
Cost per taskPredictableUnbounded until capped
LatencyBounded by the graphBounded by the iteration limit
DebuggingStandard tracingRead the trajectory and infer intent
FailureA step errorsIt loops, or stops early and reports success
Right whenThe steps are knownThe steps genuinely cannot be known in advance
Permanent rule

Build the workflow first. Reach for an agent only when the sequence genuinely cannot be enumerated in advance. Most tasks described as agentic are workflows with a branch, and implementing them as agents buys unpredictable cost and latency in exchange for flexibility that is never used.

21. The agent loop, and where it breaks

Key insight

Tool descriptions are prompt engineering with consequences. The model chooses a tool by reading its description, so an ambiguous description is not a documentation problem — it is a defect that produces wrong actions. Most agent reliability work is rewriting tool descriptions and tightening schemas, not changing the model.

Permanent trap

Shipping an agent without a hard budget. An agent that loops is a bill that grows on its own, in production, at three in the morning. Every deployed agent needs an iteration cap, a token budget and a wall-clock limit before it is exposed to real traffic, not after the first incident.

22. Multi-agent, and when it is the wrong answer

Layer 5 · Agents

The common structure across everything that has succeeded is a short distance between output and verification. Where a person sees the result immediately and can reject it cheaply, models are already dependable enough. Mental model

Deployment readiness is not a property of the model. It is the ratio between the cost of a wrong output and the cost of checking it. Reduce the checking cost — citations, structured output, diffs, previews, reversibility — and tasks that looked impossible become routine without the model changing at all.

24. Evaluation is the whole discipline

Cross-cutting · Governance

Without evaluation there is no way to know whether a change improved anything. Every prompt edit, model swap, quantisation change, retrieval tweak and tool rewrite is otherwise a guess, and the accumulated result is a system nobody can reason about.

MethodHowSuitsWeakness
Exact matchCompare against a known answerClassification, extraction, routingOnly where one answer is correct
Programmatic checksAssertions on structure and contentSchema validity, required fields, code that runsSays nothing about quality
Model as judgeA model scores output against a rubricOpen-ended text at scaleBiased toward length, fluency and its own style
Human reviewPeople score a sampleGround truth, calibrating the judgeSlow, expensive, does not scale
Online metricsAcceptance, edit distance, escalation rateThe only measure of real valueLagging; needs traffic

Public benchmarks and what they are for

Benchmarks are useful for shortlisting and useless for deciding. As at September 2026 the reported leaders differ by benchmark — GPT-6 Astra leads GPQA Diamond at 96%, while Claude Opus 4.7 leads SWE-bench Verified at 87.6% — which is itself the lesson: no model leads everywhere, and none of these tasks is your task.

Permanent rule

Fifty examples from your own traffic, with expected outputs, beat every public benchmark. Build that set before the first optimisation, keep it in version control, and run it on every change. It is the cheapest artefact in the stack and the one that makes every later decision possible.

Permanent trap

Judging with the same model family that generated the output. Model-as-judge scoring inherits its own preferences and reliably scores its own style higher. Use a different family for judging, calibrate the judge against human labels on a sample, and re-calibrate when either model changes.

25. Guardrails, and the capability–permission split

The most important control is the one that cannot be argued with by a prompt. Instructions inside the context can be overridden by other instructions inside the context; a permission check in the execution layer cannot. Anything genuinely consequential belongs in code, not in the system prompt.

Prompt injection is the unsolved one

Any content the model reads — a web page, a document, a tool result, an email — may contain instructions addressed to the model. Because the model processes instructions and data through the same channel, there is no complete defence, only reduction: treat all retrieved content as untrusted, never grant a tool an authority the requesting user does not have, and require confirmation for actions with external effect.

The structural change of 2026

The defining architectural pattern of September 2026 is not an attention variant. It is the separation of a model's intelligence from its permission to use that intelligence. Three of the month's four frontier releases shipped a general model alongside a gated, security-focused tier — the capability converging across labs while access is deliberately tiered. Anthropic's Mythos 5.1 carries weights identical to Fable 5.1 with safeguards removed for vetted defenders; Google shipped a cyber-gated Gemini variant; OpenAI's Astra restricts only its most advanced cyber capability.

Key insight

For anyone building on these models this changes procurement, not architecture. The same underlying capability may be available under different terms, with different eligibility and different contractual duties. Capability is no longer the only axis of model selection; permission is now a second one.

Permanent rule

Measure before optimising, at each step separately. Almost every AI system is slow and expensive for one dominant reason, and it is rarely the reason the team assumes. The instrumentation to attribute latency and cost per stage is the first thing to build and the last thing anyone builds.

What must survive

A model is a file of frozen numbers. Parameters and precision decide the file size, and the file size decides the machine.

The token is the unit of pricing, context, throughput and rate limiting. Every cost question reduces to how many tokens moved.

Training is compute-bound and happens once. Inference is bandwidth-bound and happens forever. Compare memory bandwidth and capacity before FLOPS.

At production concurrency the KV cache is usually larger than the weights.

The model is one layer of six, and almost every production failure happens in the other five.

Prompting, then retrieval, then fine-tuning, then pretraining — in that order of cost and in that order of how often each is the right answer. Fine-tuning changes behaviour, never knowledge.

A mixture-of-experts model is stored at its total parameter count and computed at its active one.

Output tokens cost five to six times input, and reasoning tokens are billed as output. Cap length before optimising anything else.

Tiered routing is the largest cost lever at the inference layer and requires no model change.

Reranking is the highest-return single addition to a retrieval system, because similarity and relevance are different objectives.

MCP connects agents downward to tools; A2A connects agents sideways to each other. Read-only tools before write tools, always.

Build the workflow first. An agent is justified only when the sequence genuinely cannot be enumerated. Every deployed agent needs an iteration cap, a token budget and a wall-clock limit before it sees traffic.

Tool descriptions are the selection mechanism, so ambiguity in them produces wrong actions, not merely poor documentation.

Anything consequential belongs in an execution-layer permission check, never in the system prompt. Instructions in context can be overridden by other instructions in context.

Fifty examples from real traffic beat every public benchmark. Build the set before the first optimisation.

Deployment readiness is the ratio between the cost of a wrong output and the cost of checking it. Lower the checking cost and hard tasks become routine without the model changing.
